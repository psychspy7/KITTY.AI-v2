# KITTY AI 2.0 handover

## Open and run
Use this independent project directory. Android source is android/app/src/main; backend is backend/src; owner console is admin/src. Install Node dependencies using npm ci. The scripts/install-android-tools.ps1 helper regenerates project-local Android/Gradle tools. `./scripts/build-android.ps1 -Release -BackendUrl https://kitty-ai-v2.kitty-ai.workers.dev -VersionCode 11 -VersionName 2.0.0` uses private owner signing material. For future versions choose a higher code.

Firebase public Android configuration is android/app/google-services.json. It is safe to include in the private source handover and intentionally excluded from GitHub. The Android app ID/package and web client must match the existing Firebase project. Changing them breaks login/update compatibility. Firebase rules and indexes are in firebase/; deploying --only firestore does not change Google login or the browser Hosting page.

## Private restore checklist
Retain separately: original owner keystore and android/keystore.properties; .tooling/signing/password.dpapi (Windows-user protected); backend/.vault-key.local; private Cloudflare/Firebase CLI sessions under .tooling/account-config; gateway private backup; Aiven/Hyperdrive configuration and website's own encrypted runtime. Never put these into a shareable ZIP, Git, APK or chat. Saved live provider/payment keys already reside encrypted in D1. The vault backup must match existing ciphertext; rotating it without re-encryption breaks providers/payments. The exact owner identity must match the existing UID/email. Website server gateway and Worker secret must remain identical.

## Knowledge lifecycle
Reference sources: https://huggingface.co/datasets/Salesforce/wikitext, pinned revision recorded in knowledge/manifest.json. CC-BY-SA 3.0/GFDL, Wikipedia contributors; text is adapted/packed, not model training. Per-article source URLs are retained. Historical corpus may omit current developments; retrieval avoids explicitly current/high-stakes queries. The library is public reference data, distinct from private memories and user transcripts.

Reproduction: install knowledge/requirements.txt in .tooling/python-libs; run scripts/prepare-knowledge.py then scripts/pack-knowledge.py. Preparation may deliberately stop when the initial per-article layout exceeds the reserved write quota; packing reduces it before importing. Verify the manifest, deploy restricted Firestore rules/indexes, then scripts/import-knowledge.mjs uploads with the existing exact-owner CLI session. It reserves 18,000 writes and 500 MB content, uses 100-write batches with at most three in flight and resumes .tooling/knowledge/upload-progress.json. Never enable billing to bypass a free quota. The raw dataset/cache is downloadable/reproducible and excluded from the small source ZIP; it is already stored in the deployed Firebase database after successful import.

Firestore default database STANDARD, region asia-south1, freeTier true. Published chunks: kitty_library; manifest: kitty_library_meta/current. Content/title/source/metadata index exemptions reduce overhead; a published+keywords composite supports bounded queries. Rules default-deny everything else. Google-verified users can read published data with list limit 4; exact owner can publish schema-valid documents. Main backend references use 2.5 s timeout, max 3,200 context characters and up to 32 public-cache entries. A failed library lookup must not break the reply. Firestore daily read/egress quotas still limit high traffic; free is an allowance, not unlimited capacity. Owner knowledge dashboard reports import metadata.

## Website and payments
Website source is a separate Git repository and Studio identity is separate. Same Firebase Google account binds Android membership to website purchasing. Membership webhook /api/memberships/webhook is separate from service/donation webhook. Source docs/MEMBERSHIPS-SETUP.md and private helper status describe activation. Do not rerun credential provisioning merely to monitor: it intentionally pauses checkout. LISA preorders are website reservations, not app entitlements. Feedback rewards remain disabled. Keep approved finite terms and no automatic debit.

## Checks and release
npm run check; npm run test; npm run build -w admin; backend Wrangler dry run. Android release helper runs compile, unit tests and lint. No connected phone means UI/auth/payment flows need user acceptance. See docs/RELEASE-2.0.md for actual final evidence and artifact hashes. Preserve signed older releases. Publish APK to admin/public/downloads, build console, deploy existing Worker, then scripts/prepare-update-metadata.mjs validates hosted APK before updating only the trusted release manifest. No provider/core/membership reset. Commit/push only this repo; no secret files. Refresh Source File Zip/kitty-ai via the canonical updater after verification.

## First-time tools on another Windows PC
Install Node LTS, Python 3 and a supported JDK for the Android Gradle plugin. Run npm ci, install the official Firebase CLI using npm install --global firebase-tools, and use the normal private firebase login and Wrangler login flows. Do not import tokens/passwords through chat. The helpers expect the official Firebase CLI installed under the Windows APPDATA npm directory and project-local tool caches. Read the repository's existing BEGINNER guide for Firebase certificate/account steps. The public source/library are included in the handover ZIP; provider secrets and original signing material must be restored from your separate private backup. The full handover ZIP additionally includes the 500 MB source-attributed packed public corpus, so you can restore that input without redownloading it.
