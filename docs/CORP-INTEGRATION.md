# KITTY CORP public product integration — 14 October 2026

This is a backend-only extension of KITTY 2.0.0. No Android package, signing identity, update manifest, payment setting, provider secret, personal memory store or other application source is replaced.

Both Android chat and the existing website-assistant gateway now receive the same public product directory and capability boundaries. KITTY can describe its company and link KITTY AI, LISA AI, SecretChat, Sentinel, projects, memberships, support and feedback. Core identity/personality still comes from the existing owner-controlled prompt. Google account verification and finite memberships remain unchanged.

When a company/product question or recent conversation calls for it, the Android route reads visible published content only from the fixed HTTPS pages /company, /products, /lisa-ai, /secretchat and /sentinel on kittycorp.vercel.app. It selects company plus one relevant page, cites original URLs and records retrieval timestamps. Ordinary unrelated questions do not trigger these fetches. Existing website chat already receives published company context from its website server; its directory now matches Android. Company questions use these official references instead of the historical WikiText library.

GET https://kitty-ai-v2.kitty-ai.workers.dev/api/corp is the shared public JSON directory (schemaVersion 1). Public clients may read it across origins; it exposes no accounts, tokens, inboxes, memories, payment ledgers or private chat data. GET/OPTIONS only; user-supplied source URLs do not select fetch destinations. Other backend routes retain their original authentication and origin checks. Other product owners can consume this public directory without new service credentials. No new LISA/SecretChat binary is required for KITTY to explain those products; this does not add private-data synchronization or remote-control tools to either app.

Network bounds: fixed-origin GET requests, redirects refused, no forwarded Google token/query/body, 1.8-second fetch deadlines, 256 KiB page limit, scripts/forms/comments omitted, only visible main-page text retained. Successful public-page results cache for one hour per Worker isolate; failures back off for five minutes and leave the baseline directory available. Concurrent lookups share only public page work. Excerpts in model context are bounded by UTF8 bytes and are treated as quoted facts, never commands. Public pages can contain outdated listings; KITTY's verified update manifest is the source for its own APK version. No release date, preorder activation or cross-product access is inferred.

To manage public facts, publish changes through the existing KITTY CORP website Studio. New reads pick them up after the cache expires; baseline link changes require updating backend/src/corpContext.ts and deploying the existing Worker. CORP_CONTEXT_ENABLED=false stops public page retrieval while retaining the baseline directory. There is no new provider, paid dependency, database migration or billing activation.

Validation: backend/admin type checks, 85 backend tests (including public-only routing, fixed source destinations, scripts/form exclusion, no forwarded tokens or private questions, cancellation, failure backoff, oversized pages, UTF8 bounds, cache reuse, authenticated chat injection and existing payment/account regressions), actual workerd compatibility/HTTP regression, and Worker dry run passed. Deployed catalogue/page-source and protected-route checks are recorded below after publication. Fixture tests establish prompt delivery and streaming; they do not constitute fresh Android phone acceptance or a real paid purchase.
